# EBS — Asset Path Map

Record of which image paths the code references, whether the file exists, and
what still needs replacing. Originally scoped to the home page during the
Medrano's → EBS path migration; **re-audited site-wide 2026-08-23** by grepping
every `/images/` and `/videos/` reference in `src/` and checking it against
`public/`. **Re-audited again 2026-08-30** after the section-rebuild run
(services grid, portfolio gallery, stats band, trust badges). **Re-audited
again 2026-08-31** after the About / Contact / service-page run, this time
by script rather than by hand — see the note below, because the hand method
had been missing an 8 MB file. **Re-audited again 2026-09-01** after the
city-landing run, by script; that scan needed two corrections of its own before
it could be trusted, both recorded in the orphan section.

⚠️ When re-auditing, match on QUOTED paths (`"/images/…"`), not bare
filenames. Several wrappers now name old assets in their comment blocks to
explain why they were dropped, and a plain `grep -F` on the basename counts
those mentions as live references — it reported zero orphans on this run
until the query was tightened.

⚠️ **AND THE TRAP HAS AN INVERTED FORM, found 2026-08-31.** Quoting is not
sufficient either: comment blocks now contain FULLY QUOTED paths, because
the convention on this project is to explain a dropped asset by naming it
exactly. `"/images/services-bg.jpg"` currently appears in three files and is
LIVE in only ONE (`Landing1-HeroWrapper.tsx:45`); the other two are prose
inside `/* … */`. A quoted-path grep therefore OVERSTATES live references,
where a basename grep overstated them differently. Neither is decisive on
its own — open the line and check whether it is code.

⚠️ **SCAN `public/videos/` AND `public/logos/`, NOT JUST `public/images/`.**
Every previous pass of this file counted images only. That is how an
**8.1 MB orphaned video** sat unlisted through three audits while the orphan
total was being reported as "~1.1 MB". The real figure is **8.9 MB**.

Renaming a file in `public/` without updating the wrapper (or vice versa)
produces a silent 404 — no build error, no console warning, just a missing
image. That is why this file exists.

⚠️ **THE SCAN ITSELF FAILED TWICE BEFORE THIS TABLE WAS TRUSTED**, both
times producing a confident wrong answer. Recorded because the next re-audit
will hit the same two:
1. **It walked `.md` files**, so this file's own quoted examples and the
   handoff's quoted paths counted as live references. That is the INVERTED
   trap already warned about at the top of this file, and it bit on the very
   run that was meant to respect it. **Scan code files only.**
2. **Its path regex required an `/images|/videos|/logos|/coupons` prefix**, so
   `/favicon.png` — referenced from `Layout.astro:46` as a root-level path
   — was never collected, and the favicon was reported as a 101 KB orphan
   it is not. **Match any root-relative asset path, not just the four folders.**
Comments are now stripped before matching, and sizes come from
`os.path.getsize`, never `ls | awk` (root brief: the username contains a space,
so awk's `$5` is the GROUP ID, not the byte count).

⚠️ `/favicon.svg` is **zero bytes** and referenced by nothing.
