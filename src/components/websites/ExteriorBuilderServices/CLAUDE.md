2.2 Typography baseline
The body.theme-ebs block sets font-body (Inter), text-body and text-default-font (navy) on <body>. Headings take Barlow Semi Condensed through the heading tokens. 3. Tracking Defaults
⚠️ EBS HAS NO GTM CONTAINER YET. PUBLIC_GTM_ID_EBS is unset, and both tracking scripts in Layout.astro are wrapped in {gtmId && …}. Verified against the served HTML 2026-08-20: the GTM snippet, the click bridge, and the vanilla view_section observer are ALL absent. Every data-* attribute in the codebase is inert today.

This is deliberate (see the tracking block in client.config.ts), and the architecture is complete behind it. Setting PUBLIC_GTM_ID_EBS in Vercel activates the entire chain with zero code changes — verified by running the dev server with PUBLIC_GTM_ID_EBS=GTM-TEST0000, which emitted the GTM snippet, the noscript iframe, the click bridge, and the view observer.

Two consequences while the container is missing:
· GTM Preview is NOT available as a QA loop. Verify tracking statically instead — curl the page, grep for the attribute set, then derive the payload the bridge would build. That is the standard verification step for every section generated during the redesign.
· Renames are FREE right now. No container, no history, no GA4 joins to break. Section names, labels, and slugs decided now become permanent once traffic exists, so this is the window to get them right.

3.6.1 Two swap mechanisms — the icon button is eligible under one of them
Root §8.9 documents only the automatic swap and therefore reads stricter than the platform actually is. There are two mechanisms, and which one the container uses decides whether an icon-only call CTA can feed the Primary qualified-call conversion.

Mechanism 1 — automatic text-node swap (what root §8.9 describes). The gtag script scans for the configured number as VISIBLE RENDERED TEXT and rewrites those text nodes. href, aria-label, sr-only text, and CSS pseudo-element content are all invisible to it. An icon-only button gets nothing and degrades to click_call / Secondary tap only.

Mechanism 2 — phone_conversion_callback. Google invokes a JS callback with (formatted_number, mobile_number) once a forwarding number is provisioned, and the code assigns mobile_number wherever it wants — including an anchor whose only child is an SVG. The call still routes through the GFN, so Google telephony still measures duration server-side, so the icon button DOES feed the Primary 60s conversion.

EBS should use Mechanism 2. It is not merely a workaround for the hero icon; on this codebase it strictly dominates Mechanism 1 (see the always-mount case below).

Implementation contract for EBS, when the container is built:
· Patch every tel: anchor, not just the icon. There are 11 across 9 wrappers — count RE-CONFIRMED 2026-09-01 after the city-landing rebuild; one global pass covers them all.
  const applyGfn = () => { if (!gfn) return;
    document.querySelectorAll('a[href^="tel:"]:not([data-gfn-applied])')
      .forEach(a => { a.href = 'tel:' + gfn; a.dataset.gfnApplied = 'true'; }); };

· MUST reapply after hydration. Every one of the 18 routes renders its page builder with client:load, so EVERY tel: anchor on this site lives inside a hydrated React island. A DOMContentLoaded-only patch races hydration and can be reverted. Park a MutationObserver on document.body rather than relying on a single post-load call.

3.6.2 GFN provisions ONLY for GCLID-carrying sessions
A forwarding number is allocated only when the visitor arrives with a valid Google Ads click ID. Organic, direct, referral, and all Meta traffic dial the real line and produce NO duration data at all. The qualified-call metric is therefore structurally Google-Ads-only.
Do not read "qualified calls: N" as an all-channel number — it is a Google Ads subset, and reconciling it against total lead volume across channels will always show a gap that is a measurement artifact, not lost calls.
Cross-channel call duration requires a pooled provider (CallRail, Twilio) that swaps for all traffic and pushes GCLID-keyed conversions back via offline import. Not worth it at single-client scale; revisit if EBS adds metros or the reporting is repriced.

3.6.3 GTM does not measure the 60 seconds
Worth stating because it changes how this is QA'd. GTM only sees browser events, and the browser has no idea what happens after tel: hands off to the dialer. Duration is measured entirely server-side by Google Ads telephony because the call physically transits their number. GTM's only job in this path is loading the config that triggers the swap.
Consequences: "Calls from website" is NOT a GTM conversion with a GTM trigger, it never pushes a dataLayer event, and it will never appear in GTM Preview no matter how long you watch. Verify it by confirming the config tag fires and a forwarding number actually renders on a GCLID session — not by looking for an event.
click_call (tap) and qualified_call_60s (duration) are two independent measurement systems that happen to describe the same phone call. Never reconcile their counts.

GA4 event-name passthrough: the Event Router pattern binds eventName to {{Event}}, so the name in GA4 is exactly what the code pushes. Build key events and Ads imports against the literal emitted names — never an alias.

4.3.1 How api/contact.ts routes env vars by siteKey
There is no per-client switch. A single envForSite(siteKey) helper builds the names from the prefix:
ts
function envForSite(siteKey: string) {
  const prefix = siteKey.toUpperCase(); // "ebs" → "EBS"
  return {
    to:   env(`${prefix}_CONTACT_TO_EMAIL`),
    from: env(`${prefix}_CONTACT_FROM_EMAIL`),
    bcc:  env(`${prefix}_CONTACT_BCC_EMAIL`),
  };
}
For EBS that resolves to EBS_CONTACT_TO_EMAIL, EBS_CONTACT_FROM_EMAIL, EBS_CONTACT_BCC_EMAIL. env() trims and treats an empty string as undefined, so an accidentally-empty dashboard variable behaves as missing rather than as a poisoned value. The confirmation email's display name comes from src/lib/clientRegistry.ts, keyed by the same siteKey ("ebs" → businessName "Exterior Builder Services"; fromName and replyTo are unset and fall back). Adding a client touches the registry and the dashboard only — zero API code.

7. EBS-specific methodology
Patterns this build established that root CLAUDE.md does not spell out. They are recorded here because each was learned expensively and each will recur on the next fork.
7.1 The CLAIMS REGISTER is a gate, not a reference. Every piece of customer-facing copy — wrapper defaults, data records, per-route SEO descriptions, meta titles, image alt text — is checked against EBS_HANDOFF_Step0-Step1.md §3 before it ships. A reference site's copy is raw material, not a source: three sections built from competitor references had "24/7", "insurance claims", "Owens Corning" and "No Upfront Costs" stripped as either banned or unverified. Dropping is the fix; rewording a banned claim is not.
7.2 Owner overrides are RECORDED where the value lives, dated, with the objection. Two exist: "OSHA Certified" (client.config.ts vocabulary, 2026-08-27) and the committed .env (§4.3, 2026-09-02). The record exists so a later session does not "correct" a deliberate decision, and so the reasoning is one grep away if the decision is revisited. Any future override follows the same shape: the value, the date, the rule it overrides, and "made with the objection in front of him".
7.3 Defaults are content. Root §13.3.8 in both directions was the single most expensive lesson of the redesign: four wrappers shipped the previous client's copy or a 404 image for weeks because their defaults READ as unreachable placeholders while the builder passed no prop. Before editing any default, grep every call site; before trusting any default, do the same. The structural fix is a REQUIRED field on the data type (heroImage, heroImageAlt) so omission is a type error.
7.4 Prefer Mechanism A, and count hooks before assuming it. Seventeen sections use the vanilla [data-track-view] observer; five of those still hydrate for other reasons and are on Mechanism A anyway because it fires earlier. A wrapper with no hooks of its own can still need hydration through an imported Radix-backed Subframe primitive (FullStretchFaqWrapper). A native <details> accordion (ServiceONEFaqWrapper) needs none. The grep hazard: five files mention "IntersectionObserver" in comments explaining its removal; count observers that push to dataLayer, not the word.
7.5 Measure contrast on pixels, and re-measure when anything moves. getComputedStyle cannot see a photograph under a scrim, a gradient with varying alpha, or a tint painted by child layers. Every scrim opacity and gradient stop in this build is a measured number (service-hero 72%, credential band 24px/600, city-hero stops ≥40% apart) and each is annotated in §3.3 with the method. When a neighbour section moves, the tuning that referenced it is stale (landing-services was retuned twice in one day for exactly this reason).
7.6 Verify the probe before believing the failure. Roughly twenty false alarms on this client were the harness, not the site: a dead dev server, a selector guessing the wrong tag, querySelector returning the hidden half of a desktop/mobile pair, a status-only sweep that cannot see a 404 image, a fabricated GCLID, a map probe on a page that has no map. Confirm the probe sees a control it should see, then report.
7.7 Two sources of truth is the default failure. The intake, the config, the handoff, and this file have each been wrong about the other at some point (the email, the tsconfig value, the env-var table, the route list). When a value is corrected, correct it everywhere it is stated in the same commit, and prefer deleting a duplicate statement to updating it.

9. Future-Client Migration Notes
What this fork taught about forking. Root CLAUDE.md §13.10 and DUPLICATE.md are authoritative for the procedure; these are the EBS-specific additions.
9.1 What's template-shared (don't change per-client)
All of src/ui/ (Subframe-generated). src/layouts/Layout.astro — including the og:image absolutization, the click bridge and the vanilla view observer; only the Google Fonts <link> and the favicon path are per-client concerns. src/styles/global.css's Tailwind entry and theme.css import. astro.config.mjs, tsconfig.json, package.json. src/pages/api/contact.ts and src/lib/clientRegistry.ts's shape (a new client is one registry entry plus env vars). The og/ renderer PIPELINE (renderSocialShareCard.ts) is reusable as-is; the CARD (SocialShareCard.tsx) is per-client.
9.2 What changes per fork — additions EBS surfaced
Beyond DUPLICATE.md Steps 0–10: (a) the og:image card — its colours are literals mirroring the new theme block and its assets are the new client's photo, logo and heading font; (b) the favicon — regenerate public/favicon.png from the new mark, and check it on a dark tab; (c) per-route SEO descriptions are claims surfaces too, and city descriptions should not share one template; (d) the CLAIMS REGISTER is built at intake, before any copy is written, with an explicit cleared list, a MUST-NOT-SHIP list, and an UNVERIFIED list — the third category is where most reference-site copy lands; (e) grep the served HTML of every route pattern for the previous client's name, trade terms, cities, year and region label — source greps miss defaults that ship (§7.3); (f) decide the tracking slugs (city scheme, service default, section names) before the container exists, because they freeze at first traffic; (g) when the client has no domain yet, the Vercel starter URL works for everything except the Resend sender and the printed siteUrl.
9.3 First-fork validation steps
DUPLICATE.md Step 9 plus, from this fork: run root §11.8's status-AND-bytes sweep on the live URL, then fetch every og:image and preload URL (a healthy 200 page can carry a 404 image); confirm the PUBLIC_ values were inlined by grepping the served JS chunks, not the HTML; confirm the five runtime env values exist in the dashboard, not just in a file; and run Step 10's own exit check — grep the generated CLAUDE.md for the previous client's name, case-insensitive, and require zero hits.
9.4 Per-client CLAUDE.md drift discipline
Root §13.9.4 applies: Open Items reflect actual codebase state; resolve by marking, never by deleting.
